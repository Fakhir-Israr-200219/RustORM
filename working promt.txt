### Ab kya reh gaya?

Humne pehle jo roadmap rakha tha usmein next **CRUD Edge Cases + API Freeze** hai.

Is stage mein naye features nahi daalne. Pehle existing CRUD ko production-level consistency ke liye check karna hai:

1. **Empty update**

   ```rust
   TestUserUpdate { name: None }
   ```

   → predictable error hona chahiye.

2. **Update/Delete nonexistent ID**
   → behavior decide karna hai: error ya affected-row `0`.

3. **Empty `create_many()`**
   → already handled hai, test add karna hai.

4. **Empty update_many condition/data**
   → invalid cases define karne hain.

5. **Empty delete_many condition**
   → sab rows accidentally delete na ho jayen — **ye especially important hai**.

6. **Multiple conditions**

   ```rust
   TestUser::name.eq("Alice")
       .and(...)
   ```

   → UPDATE MANY / DELETE MANY mein bind ordering verify karni hai.

7. **Parameter numbering**

   ```sql
   UPDATE users
   SET name = $1
   WHERE name = $2
   ```

   → already basic test hai, lekin compound condition bhi test karenge.

8. **API consistency**

   ```text
   create
   create_many
   update
   update_many
   delete
   delete_many
   ```

   Sabka return type/error behavior logically consistent karna hai.

### Uske baad

Phir hum **CRUD API freeze** kar sakte hain.

Uske baad actual next major area hoga:

> **READ / Query API expansion**

Yani `find()` ko serious ORM querying mein expand karna:

```rust
User::find()
    .where_(...)
    .order_by(...)
    .limit(...)
    .offset(...)
    .all(&db)
```

Tumhare query engine mein already kaafi cheezen hain — joins, relations, aggregates, group by, having, subqueries, etc. — isliye ab humein randomly features add nahi karne. **Existing query system ko CRUD ke saath ek coherent public API banana hai.**

**Mera suggestion:** abhi seedha READ features par jump na karein. Pehle **CRUD edge-case tests + API freeze** complete karte hain.
