## Aur `.rustorm` architecture lock

Ye distinction main aage maintain karunga:

```text
                 RUSTORM
                    │
        ┌───────────┴───────────┐
        │                       │
   rustorm runtime          rustorm-cli
        │                       │
        │                 schema.rustorm
        │                       │
        │                 Schema AST
        │                       │
        │              ┌────────┴────────┐
        │              ↓                 ↓
        │         entities          migrations
        │
        ↓
      SQLx
        ↓
    Database
```

**`schema.rustorm` → source of truth**

**`entities/` → generated application-specific code**

**`migrations/` → generated/versioned migration history**

**`rustorm` → generic runtime**

**`rustorm-cli` → generator/migration tooling**

Ye separation hamari architecture ka fundamental rule rahega.

Aur haan bhai — **abhi hum isi runtime ko file-by-file nahi, concept-by-concept mature karenge.** Current `User` implementation ko bhi isi liye final architecture nahi samjhenge; ye generated entity ka temporary manual stand-in hai.
